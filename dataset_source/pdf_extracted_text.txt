AI-Optimized IDDQ Test Time Reduction
1. Executive summary
Machine learning can cut IDDQ test time by removing redundant vectors, shortening settling
waits and skipping low-risk die, while keeping or improving defect screening. IDDQ remains
one of the slowest tests per vector because each quiescent-current measurement must wait
for the supply to settle. In advanced nodes, high and variable background leakage also makes
fixed pass/fail limits weak.
This document describes six complementary optimization levers:
1. Vector reduction — keep only the IDDQ states that add unique defect detection.
2. Settling-time prediction — estimate the settled current from early transient samples.
3. Adaptive per-die test — run a reduced IDDQ set on die predicted to be low-risk.
4. ML-based outlier screening — replace fixed limits with leakage-normalized, multivari-
ate screens.
5. Spatial prediction — model wafer leakage maps so only deviations need full measure-
ment.
6. Flow ordering — place high-fallout vectors early so failing die stop sooner.
The main risks are test escapes (higher DPPM), model drift across lots and process changes,
and customer or automotive acceptance.
Every lever therefore ships with guard-bands, a
full-test audit sample and downstream escape tracking.
All time and savings figures in this document are illustrative planning values. They must be
replaced with measured data from your product and tester before any decision.
2. Background: IDDQ testing
2.1 Principle
A fault-free static CMOS circuit draws only leakage current from VDD when no inputs are
switching. Many physical defects create a conducting path from VDD to ground in a given
logic state, which raises the quiescent supply current (IDDQ) by orders of magnitude above
leakage in older nodes. IDDQ testing applies a set of vectors that put the circuit into chosen
quiescent states, waits for transients to decay, then measures supply current per state.
2.2 Defects IDDQ detects well
• Bridging faults (resistive shorts between nets), including those that do not cause a logic
error.
• Gate-oxide shorts and pinholes.
• Transistor stuck-on and leaky junction defects.
• Floating gates and some open defects that leave a node at an intermediate voltage.
• Latent reliability defects that may escape functional and scan tests but fail early in the
field.
2.3 Why IDDQ is harder in advanced nodes
• Background leakage is high. Subthreshold, gate and junction leakage grow as dimen-
sions shrink, so the defect current is a small fraction of total current.
• Leakage varies widely. Die-to-die and wafer-to-wafer process variation spreads normal
IDDQ over a wide range, so a single fixed limit either fails good die or passes defective
ones.
• Strong temperature and voltage dependence. Leakage changes sharply with tem-
perature and VDD, so test conditions must be tightly controlled.
• Many power domains. Modern SoCs have multiple rails and power-gated islands, mul-
tiplying measurements.

2.4 Derived IDDQ metrics
To separate defects from normal leakage, production flows use relative metrics rather than
raw current:
• Delta-IDDQ — the difference between IDDQ of consecutive or sorted vectors. A defect
active only in some states creates a step.
• Current ratio — max IDDQ divided by min IDDQ for a die. Normal die have a stable
ratio regardless of absolute leakage.
• Nearest-neighbor residual (NNR) — the die’s IDDQ minus an estimate from surround-
ing die on the wafer, removing spatial leakage trends.
• Multi-condition IDDQ — IDDQ at several voltages or temperatures, where defects scale
differently from leakage.

4. AI/ML optimization techniques
The six levers below are independent and can be deployed in stages; vector reduction and
settling prediction are offline or low-risk and usually come first.
4.1 IDDQ vector selection and reduction
Goal: the smallest vector set that keeps defect detection.
Inputs
• Fault-simulation coverage per vector for bridging, pseudo-stuck-at and leakage fault mod-
els.
• Historical per-vector IDDQ for passing and failing die across many lots.
• Unique-fail attribution: which die failed only on a given vector.
Methods
• Greedy set cover — repeatedly pick the vector that adds the most uncovered faults or
historical fails. Fast and explainable baseline.
• Genetic algorithms or simulated annealing — search vector subsets with a fitness function
of coverage minus a time penalty.
• Reinforcement learning — an agent adds or removes vectors, rewarded for retained cov-
erage and reduced time. Useful when vectors differ in settling time or rail count.
• Correlation clustering — cluster vectors whose IDDQ readings are highly correlated
across die; keep one representative per cluster.
Output: a ranked vector list and a coverage-versus-count curve, from which the team picks
a knee point with margin.
4.2 Settling-time prediction
Goal: stop waiting before full settling by predicting the final current.
Approach
1. Capture several fast samples of supply current during the early transient after each vec-
tor.
2. Fit a model that maps the early samples to the fully settled value measured in character-
ization.
3. In production, accept the prediction when its confidence interval is narrow and far from
the limit; otherwise wait for full settling.
Model options
• Physics-informed fit: sum of one or two decaying exponentials plus a constant, solved for
the constant.
• Gradient-boosted trees or a small neural network on sample values, slopes, vector ID,
rail and temperature.
• Quantile regression or conformal prediction to produce calibrated confidence bounds.
Constraints: requires tester hardware that can sample the transient quickly, and character-
ization data with full settling for training.

4.3 Adaptive per-die IDDQ
Goal: run the full IDDQ set only where it is likely to matter.
Inputs available before IDDQ
• Parametric tests: leakage at other conditions, Vmin, Fmax, ring-oscillator frequencies,
process monitor readings.
• Wafer position (radius, edge distance, reticle position) and neighbor results.
• Lot and wafer context: equipment history, inline metrology if available.
Method
• A classifier or anomaly score estimates each die’s risk of an IDDQ fail.
• Die below a risk threshold run a reduced vector set; die above it, or with missing inputs,
run the full set.
• A fixed random fraction of die always run the full set as an audit sample.
Infrastructure: real-time adaptive test hooks on the tester or test-cell controller that can
read upstream results and switch flows within the die’s test time.
4.4 ML-based outlier screening
Goal: catch more true defects with fewer measurements by screening against what normal
looks like for that die.
Methods
• Statistical baselines: delta-IDDQ, current ratio and NNR (Section 2.4).
• Multivariate distance: Mahalanobis distance across all vectors, rails and conditions, us-
ing a robust covariance estimate.
• Regression residuals:
predict expected IDDQ from leakage-correlated parametrics;
screen on the residual.
• Unsupervised anomaly detection: isolation forest, one-class SVM or autoencoder recon-
struction error on IDDQ signatures.
• Gaussian process or spatial models: expected IDDQ from wafer position, screening the
residual.
Benefit to test time: better separation lets the program drop redundant conditions and
reduces marginal retests, because fewer die land near a fixed limit.
4.5 Spatial and wafer-level prediction
Goal: reduce the number of die that need full-depth measurement.
• Measure the full IDDQ set on a sample of die per wafer.
• Reconstruct the wafer leakage map using Gaussian process regression or compressed-
sensing (virtual probe) methods.
• Measure the remaining die with a short set and compare against their predicted value;
any deviation triggers the full set.
4.6 Test-flow ordering
Goal: lower average time per die by failing defective die sooner.
• Rank vectors by historical fail probability per unit time.
• Place the highest-yield-loss vectors first, subject to dependencies.
• Combine with stop-on-first-fail where datalogging requirements allow.

6. Model development
Models are trained offline on full-test data and judged first on escapes (missed defective die),
then on time saved.
6.1 Data requirements
• Full IDDQ data for every vector, rail and condition, without stop-on-fail, over many lots
and wafers.
• Settling transients sampled at high rate for a characterization subset (for 4.2).
• Upstream parametric results and die coordinates linked by unique die ID (ECID or
lot/wafer/x/y).
• Downstream outcomes linked to the same die: final test, burn-in, system-level test and
customer returns. These are the labels that define a true defect.
• Tester, site, probe card and temperature metadata, to detect equipment effects.

7.2 Guard-banding rules
• A prediction is used only when its confidence bound sits clear of the limit by a set margin.
• Die with any missing input, unusual context or new equipment run the full flow.

• A fixed audit fraction of die always runs the full flow, chosen randomly so it cannot be
gamed by the model.
• Any lot that trips a drift alert reverts to the full flow until reviewed.
7.3 Automotive and high-reliability products
Automotive products qualified under AEC-Q100 and used in ISO 26262 systems typically have
strict DPPM targets and change-control requirements. For these products:
• Treat any test reduction as a formal process change requiring customer notification or
approval.
• Prefer outlier screening improvements (which tighten screening) over test skipping.
• Keep full traceability: model version, threshold and flow decision recorded per die.
• Validate against burn-in and field data over a longer period before release.
7.4 Monitoring in production
• Daily dashboards: test time saved, audit-sample escape rate, overkill, drift indicators.
• Escape investigation loop: every downstream fail of a die that took the reduced flow is
analyzed and fed back to training.
• Model governance: version control, approval records and rollback plan for every de-
ployed model.
